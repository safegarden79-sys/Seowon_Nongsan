# 서원농산 실시간 낙찰 수집기 (OCR 아님, 직접 읽기)

경매가 진행되는 요일·시간대 동안 서울청과·동화청과 사이트에서 "내가 낙찰받은 줄"을
2초마다 직접 읽어서, **바뀐 게 있을 때만** 바로 서원농산 서버
(`seowon-nongsan-zjyr.onrender.com`)로 올려주는 작은 프로그램입니다. 화면을 찍어서
글자를 인식(OCR)하는 방식이 아니라, 두 사이트가 실제로 가지고 있는 값을 바로
읽어오기 때문에 더 빠르고 정확합니다.

## seowon_bridge.py — 서버로 보내는 다리

실제 전송과 상태 신호는 `seowon_bridge.py` 의 `Bridge` 클래스가 맡습니다
(`main.py` 가 하나 만들어서 두 수집기(`seoul_poller`/`donghwa_poller`)가 나눠 씁니다):

- **`heartbeat(시장, "ok"/"expired"/"error", rows=, interval=)`** — 시장 화면을 한 번
  읽을 때마다(성공·실패 상관없이) 부릅니다. 서원농산 앱 최상단 오른쪽 `서울 ● 동화 ●`
  툴바를 녹색(정상)/빨강(만료·오류)으로 바꿔 줍니다. 신호가 `max(30초, 확인간격×3)`
  보다 오래 끊기면 앱에서는 회색(신호 없음)이 됩니다.
- **`send_lots(rows)`** — 바뀐 낙찰 줄을 보냅니다. 줄마다 "사이트에서 처음 본 시각"을
  붙여서, 서버가 사이트→서버 지연(목표: 3초 이내)을 잴 수 있게 합니다.
- 전송은 Bridge 안의 별도 스레드가 하므로, 서버가 느리거나 잠깐 끊겨도 사이트를 읽는
  반복문은 멈추지 않습니다. 못 보낸 낙찰 줄은 잃지 않고 다음에 다시 보냅니다.
- **조회 날짜가 시장마다 다릅니다** — `query_dates(시장)` 으로 사이트에 넣을 날짜(들)를
  구하고, 그 날짜로 읽은 줄에는 `auction_date(시장, 조회날짜)` 로 앱에 올릴 "경매일"을
  붙입니다. 동화청과는 밤 경매가 다음날 날짜로 조회되고, 서울청과는 그날 달력 날짜(자정에
  바뀜)로 조회됩니다 — 둘 다 앱에는 "경매가 끝나는 날" 하나로 맞춰 올라가므로, 한
  경매가 날짜만 다른 두 줄로 쪼개지지 않습니다.
- 연결만 먼저 시험해보려면: `python seowon_bridge.py <서버주소>` (비밀번호 없이, 두
  시장에 "연결 시험" 신호를 한 번 보내고 끝납니다 — 앱 쪽에 해당 툴바가 올라와 있어야
  실제로 녹색이 되는 걸 볼 수 있습니다).
- 서버가 `poll` op 를 받아 시장별 상태를 모으고(`state.pollers`), 앱이 그 상태를
  보여주는 툴바는 **서원농산 APP(server.js/index.html) 쪽에도 맞는 버전이 올라가 있어야**
  작동합니다 — poller 쪽만 최신이어도 서버·앱이 구버전이면 신호는 조용히 무시됩니다
  (오류 없이 전송은 되지만 화면에는 안 보입니다).

## 언제 자동으로 도는가 (스케줄)

이 프로그램을 **계속 켜 두면**(아래 "24시간 자동 실행" 참고), 안에서 스스로 요일·시간을
확인해서 다음과 같이 동작합니다 — 사람이 매번 켜고 끌 필요가 없습니다.

- **일·월·화·수·목·금요일** 당일 **22:30 부터 다음날 새벽 1:00 까지** 2초 간격으로
  두 사이트를 확인하고, 낙찰 내역이 바뀌었을 때만 서버로 올립니다(3초 안에 앱에
  뜨는 걸 목표로 합니다 — 확인 간격 2초 + 읽는 시간 + 전송). 실제 경매가 진행되는
  시간대만 켜 두고, 그 외 대부분의 시간(새벽 1:00~밤 22:30)은 쉽니다.
- **토요일은 "시작 요일"에서 뺐습니다** — 즉 토요일 22:30 에는 새로 시작하지 않습니다.
  그래서 실제로 쉬는 시간은 (매일 새벽 1:00~밤 22:30 의 일반적인 휴식 외에) 토요일
  22:30 부터 일요일 22:30 까지 하루를 통째로 더 쉽니다.
- 쉬는 시간에는 로그인도, 사이트 접속도 하지 않고 그냥 기다립니다(동화청과는 그 동안
  브라우저도 닫아 둡니다). 활성 시간이 되면 자동으로 다시 로그인부터 시작합니다.
- 화면에 "비활성 시간대 — 다음 활성 시간까지 기다립니다" / "활성 시간대 시작 —
  감시를 시작합니다" 가 찍히는 것으로 지금 쉬는 중인지 도는 중인지 알 수 있습니다.
- 스케줄을 바꾸고 싶으면 `common.py` 맨 위의 `ACTIVE_START`/`ACTIVE_END`
  (시작·종료 시각)와 `EXCLUDED_START_WEEKDAY`(쉬는 시작 요일, 5=토요일)를 고치세요.

## 왜 이렇게 만들었나

- **서울청과**(sfvc.co.kr): 로그인하면 `/mypage/auction.asp` 에 내 낙찰 내역이 단순한
  표(HTML table)로 바로 나옵니다. 읽기 쉬움.
- **동화청과**(donghwafp.com): `낙찰서` 화면은 Crystal Reports 라는 리포트 뷰어가
  표를 그리는데, 글자 하나하나가 좌표로 찍혀 있어서 "같은 세로줄(x좌표) = 같은 항목"
  규칙으로 줄을 다시 조립합니다. 카테고리(피망·파프리카·고추 등)를 굳이 선택하지
  않아도 — **비워 두고 검색해도 그날 전체 낙찰이 한 번에 나오는 것을 확인했습니다.**
  그래서 카테고리 코드를 하나씩 맞출 필요가 없습니다.
- 두 사이트 모두 "오늘 거래는 19시 이후에만 조회 가능"이라는 안내문이 있지만,
  실제로 낙찰서(`realtime_wonpyo`) 리포트 자체는 경매 중에도 바로바로 값이
  올라오는 것을 확인했습니다. (안내문은 다른 화면 — 정산내역 등 — 을 위한 문구로 보입니다.)

## 비밀번호는 제가(Claude) 적어 넣지 않았습니다

`secrets.example.json` 에는 비밀번호 자리에 안내 문구만 넣어 두었습니다.
**아래 1단계처럼 직접 `secrets.json` 을 만들고, 그 안에 본인 비밀번호를 손으로
입력해 주세요.** 이 프로그램은 그 파일(사장님 PC 안에만 있음)을 읽어서 로그인합니다.

## 설치 (한 번만)

```bash
cd auction_poller
pip install -r requirements.txt
playwright install chromium
```

Windows라면 명령 프롬프트(cmd)나 PowerShell에서 위 두 줄을 그대로 입력하면 됩니다.

## 설정

1. `secrets.example.json` 파일을 복사해서 이름을 `secrets.json` 으로 바꿉니다.
2. `secrets.json` 을 열어서 비밀번호 두 자리를 직접 입력합니다. (ID는 이미 넣어뒀습니다:
   서울청과 `cp372`, 동화청과 `070`)
3. `server_url`, `user`(서버에 표시될 보낸 사람 이름)은 필요하면 바꾸세요.
4. `poll_interval_sec`: 몇 초마다 확인할지. 기본 2초입니다(3초 안에 앱에 반영되는 게 목표).
   (**이미 `secrets.json` 을 만들어 쓰고 있었다면** 이 값은 여러분의 `secrets.json`
   안에 예전 값(5초 또는 10초)이 그대로 남아 있을 수 있으니, `"poll_interval_sec": 2` 로
   고쳐 주세요 — `secrets.json` 은 비밀번호가 들어있어서 이번 업데이트 파일에
   포함하지 않았습니다.)

## 실행

```bash
python main.py
```

Windows에서는 `run.bat` 을 더블클릭해도 됩니다. 창을 닫으면 멈추니, 요일·시간 스케줄이
알아서 작동하게 하려면 **이 창을 계속 켜 두어야 합니다** (쉬는 시간에는 그냥 대기만
하고 있으니 꺼둘 필요가 없습니다).

### 매일 자동으로 켜지게 하기 (PC 를 재시작해도 안전하게)

사람이 "매일 저녁 실행, 아침에 끄기"를 직접 할 필요는 없습니다 — 위 스케줄 로직이
프로그램 안에서 알아서 돌고 쉬기를 반복합니다. 다만 프로그램 자체는 PC가 켜져 있는
동안 계속 실행되고 있어야 하므로, Windows 작업 스케줄러에 **"로그온할 때 시작"**으로
한 번만 등록해 두면 편합니다:

1. 시작 메뉴에서 "작업 스케줄러" 실행 → 오른쪽 "기본 작업 만들기".
2. 이름: `서원농산 낙찰수집기` (자유롭게).
3. 트리거: "사용자 로그온할 때".
4. 동작: "프로그램 시작" → 이 폴더의 `run.bat` 선택.
5. 마침. (PC를 켜고 로그인만 해두면 그 다음부터는 신경 쓸 필요 없이 창이 자동으로 열려
   계속 돌아갑니다. 활성 시간이 아닐 때는 그냥 조용히 기다립니다.)

창을 그냥 띄워 둔 채 PC를 켜두는 기존 방식(더블클릭)도 그대로 됩니다 — 위 등록은
"PC가 재시작돼도 다시 챙겨서 켜줄" 필요가 있을 때만 하면 됩니다.

## 로그인이 끊기면

두 사이트 모두 세션이 만료되면 프로그램이 알아서 다시 로그인합니다
(`secrets.json` 안의 ID/비밀번호로). 별도로 조작하지 않아도 됩니다.
다만 사이트에서 비밀번호를 바꾸면 `secrets.json` 도 같이 고쳐야 합니다.

## 중복 전송 걱정

이미 보낸 낙찰은 `seen_lots.json` 에 기록해서 같은 줄을 두 번 보내지 않습니다.
(서버 쪽도 같은 id 는 덮어쓰기라서 혹시 중복으로 보내도 문제는 없습니다 — 안전장치가
이중으로 되어 있는 셈입니다.) 날짜가 바뀌면 자동으로 새로 시작합니다.

## 지난 한 달 치를 캘린더에 한꺼번에 채워 넣기 (백필)

서원농산 APP 의 "📅 캘린더" 탭에서 과거 날짜를 바로 조회할 수 있게 하려면,
`backfill_donghwa.py` 를 **한 번** 실행하세요:

```bash
python backfill_donghwa.py        # 최근 30일 (오늘 포함)
python backfill_donghwa.py 40     # 기간을 늘리고 싶으면 숫자만 바꿔서
```

오늘의 "작업 목록"(박스 체크·상차 체크용)에는 전혀 영향을 주지 않고, 캘린더용
기록에만 쌓입니다. 이미 받은 날짜를 다시 돌려도 안전합니다(덮어쓰기만 됨).

**⚠ 서울청과는 포함되지 않습니다.** 서울청과 사이트에서 과거 날짜 낙찰 내역을
조회하는 화면("낙찰명세서")을 직접 시도해봤지만, 날짜를 어떻게 넣어도 사이트
쪽에서 "잘못된 요청입니다"만 돌아옵니다 — 그 화면 자체가 사이트에서 고장나 있는
것으로 보이고, 저희 쪽에서 고칠 수 있는 부분이 아닙니다. 그래서 캘린더에서
**동화청과의 지난 기록은 최근 한 달 치가 보이지만, 서울청과는 poller 를 켠
시점부터만** 쌓입니다. 혹시 서울청과 쪽에 과거 조회가 되는 다른 화면이 있다면
알려주시면 다시 시도해볼 수 있습니다.
